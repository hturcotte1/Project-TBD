# Decisions

Judgment calls made during the build, with reasons. Newest at the bottom.

1. **Package scope `@apogee/*`.** The repo is `Project-TBD`; the scope is short and won't collide. Rename is a find-and-replace.
2. **Agent name: Vector.** Configurable via `AGENT_NAME`. Short, warm, gender-neutral, easy to type.
3. **REST with a shared zod contract instead of tRPC.** The contract (`packages/shared/src/api/contract.ts`) is a list of route definitions with zod params/query/body/response. Fastify registers routes from it and the web app gets a typed client from it. This keeps the API callable from webhooks, curl, and the fake phone, and avoids tRPC's coupling to a React client.
4. **Fastify over Hono.** Mature plugin ecosystem for rate limiting, multipart uploads, and static files, which the dev phone and upload flows need.
5. **Clerk in production, dev-mode auth locally.** `AUTH_MODE=clerk` uses `@clerk/nextjs` on the web and `@clerk/backend` `verifyToken` on the API. `AUTH_MODE=dev` uses an HMAC-signed cookie and `/dev/login` so the entire product runs and is testable without vendor accounts. The API verifies bearer tokens through one `AuthVerifier` interface either way. Clerk could not be exercised in this sandbox (no keys); see KNOWN_GAPS.
6. **Web app talks only to the API.** No direct DB access from Next.js. One place enforces authorization. Client components go through `/api/proxy/*` so the token never leaves the server.
7. **Deterministic extraction first, Stagehand as fallback.** The reader navigates with Playwright, captures each page's HTML, and runs cheerio-based extractors from `commonapp-map.ts`. Those extractors are pure functions over HTML, so they run in tests against recorded fixtures with no browser. Stagehand `extract()` is used only when an extractor reports low confidence for a whole section (site drift). Stagehand v4 bundles zod 4 and its own driver, so it connects to the same Browserbase session over CDP rather than sharing the Playwright page.
8. **Verification codes go through Redis, never Postgres.** A `VerificationCodeChannel` (Redis list with 10-minute TTL) carries the code from the agent tool to the waiting browser job. The browser job stays in-process while waiting because a local Chromium session cannot be resumed by another process. Browserbase sessions are kept alive with the same in-process wait for consistency.
9. **Scheduler is a 5-minute tick plus pure trigger rules, not thousands of delayed jobs.** `evaluateTriggers(state, now)` is deterministic and fully unit-tested with a fixed clock. The tick enqueues jobs with deterministic ids so re-ticks are idempotent. The `nudges` table records what was sent per `triggerKey` so nothing repeats.
10. **Deadlines are dates, resolved to end-of-day in the student's timezone.** Common App treats deadlines as 11:59 pm applicant-local. Days remaining = calendar-day difference in the student's zone.
11. **LLM default `claude-sonnet-5`, strong model `claude-opus-5`.** The prompt asked for Sonnet as the runtime default and "the strongest available model" for high-stakes reasoning. Claude Fable 5.1 has different API constraints (no forced tool use, 30-day retention requirement) and higher cost; Opus 5 is the safe default for the strong tier. Both are env-overridable.
12. **`FakeLLM` is rule-based, not a stub.** Conversation tests assert on tool calls and DB state; the fake implements the persona's decision rules deterministically (intent → tool calls → reply) so the runtime, tools, repos, messaging, and audit paths are exercised end to end. Real-model behavior is verified separately when a key is present (`pnpm test:live`).
13. **Documents go to the LLM natively.** Transcript PDFs and images are sent as `document`/`image` blocks with structured output, so there is no PDF parsing library to maintain.
14. **Storage adapter is S3-compatible.** Supabase Storage exposes an S3 endpoint, so one `S3StorageProvider` covers Supabase and AWS. Local dev writes to `.data/storage` and serves via the API.
15. **Essay text is stored, never generated.** `saveEssayDraft` only accepts text that arrived in a student message or the dashboard editor. The essay-feedback prompt returns a structured `EssayFeedback` object with no `suggested_text` field, so even a compliant model cannot hand back prose.
16. **Autonomy level lives in config and the approval kind enum.** `AUTONOMY_LEVEL=B` rejects any approval of kind `submit`; level C would allow creating and executing them through the same `approvals` → `browser_jobs` path. The writer's submit guard is a separate, always-on runtime check that level C would relax explicitly for the `submit` job kind only.
17. **Subagent model.** All implementation subagents run on Sonnet; the orchestrator (this session) does architecture, review, integration, and verification.
18. **Job ids never contain a colon.** BullMQ rejects custom ids with `:` unless they happen to split into exactly three parts, which made `sync:<id>:<bucket>` work by accident and `inbound:<id>` fail at runtime. `jobIds` now joins with `__` and sanitizes components; the memory enqueuer enforces the same rule so tests catch it.
19. **Consumed verification codes are scrubbed from the student's own text.** The inbound message row is the only place a code could persist; the `answerVerificationCode` tool replaces it with `[verification code]` after publishing to the channel, whether or not a job was waiting.
20. **Relative paths resolve against the repo root.** `STORAGE_LOCAL_DIR=.data/storage` meant different directories to the API and the worker; `loadEnv()` now resolves relative paths from the directory containing `pnpm-workspace.yaml`.
21. **Item matching requires a descriptor.** "done with the Georgetown supp" must not mark an arbitrary Georgetown item done. `matchItem` needs a title or kind word (with student synonyms like "supp", "rec", "letter") and reports near-ties as ambiguous so the agent asks which one.
22. **Non-Common-App schools keep their supplements.** Georgetown's essays are tracked as internal-rule items the student marks done, since the reader cannot observe them.
23. **Regular Decision is the default plan when adding a school.** Early Decision is binding; it must be a deliberate choice, never a silent default from dataset ordering.
24. **Teacher-recommendation slots follow the invitations.** One item per required letter plus one per extra teacher actually invited (capped at the school's max), so an optional second letter is tracked once the student asks for it.
25. **Tests run serially at the root.** All packages share `DATABASE_URL_TEST`; Turbo's default parallelism made them truncate each other's tables.
26. **Sunday's weekly plan is enqueued for the coming week.** The trigger fires Sunday evening; the worker computes the following Monday as `week_start`.
27. **Admin role follows `ADMIN_EMAILS` on every request.** Grant and revoke are symmetric; removing an email demotes the row on the next authenticated request (found by the adversarial review).
28. **Essay text never lands in verifications.** Fill verifications longer than 200 characters (and every essay path) are stored as `[N words, M chars, sha256:…]`; the match verdict is computed before redaction, so audit rows and API responses prove what was written without holding the prose.
29. **No student words, no action.** A photo-only message or an extraction run has no student text, so text-gated tools are refused outright; only an approval-origin run (a dashboard Approve click) skips the text check.
30. **Inbound media is fetched defensively.** Production accepts only public HTTPS hosts, follows no redirects, times out at 20 s, and aborts downloads over the 20 MB cap while streaming; the fake provider's local URLs are allowed outside production only.
31. **Dev routes never mount in production.** `/dev/phone` and `/dev/storage` require `NODE_ENV !== 'production'` in addition to the fake/local providers.
32. **Idempotency markers are released on failure.** A webhook event's marker row is deleted if processing throws, so the provider's retry is handled instead of dropped; unknown senders are recorded (masked) in the audit feed rather than discarded silently.
33. **The "reconnect your account" text obeys quiet hours.** It is held as a custom trigger in a delayed proactive run until quiet hours end; only day-of-deadline alerts bypass quiet hours.
34. **Proactive sends check the nudge ledger before texting.** A retried job skips batches whose triggers were already recorded, so a crash after sending cannot double-text.
35. **Nudges about recommenders and essays carry their item id.** Acknowledging or snoozing the item suppresses the recurring weekly nudge, as the spec requires.
36. **Typefaces: Hanken Grotesk for the interface, Bricolage Grotesque for the countdown only.** Chosen from a rendered bake-off (Instrument Sans, Hanken Grotesk, Schibsted Grotesk, Host Grotesk, Familjen Grotesk, Onest, Public Sans, IBM Plex Sans for the body; Bricolage, Familjen and Schibsted for the numeral) at 14px and 84px on the dark page with real content. Instrument Sans read as Inter's cousin; Schibsted crowded a 40px row; Host fell apart under 14px; Familjen's lowercase was too quirky for 300 checklist rows; Onest, Public Sans and Plex were competent and anonymous. Hanken has tabular figures by default (measured: `111` and `000` render at equal width) and the calmest body of the set. Bricolage at weight 600 reads as an instrument, not a headline. The full comparison is in `docs/DESIGN.md`.
37. **Dark-first blue-slate, with a designed light theme and a per-student theme switch.** The page is `#141D2B`, visibly not black; elevation is a lighter surface (four steps), and the single shadow exists only for floating Surface 3 elements. The brand ice blue is chrome-only; urgency is one warm signal in six steps, and green is not an urgency value. Theme follows the system by default; Settings offers dark / light / system, stored in `localStorage` as `apogee-theme` and applied by an inline script before first paint so there is no flash. Both palettes and their contrast ratios are in `docs/DESIGN.md`.
38. **Fonts are self-hosted, not loaded from Google Fonts.** The brief named Google Fonts; the same OFL files (from the Fontsource builds of the Google Fonts sources) are committed under `apps/web/app/fonts` and loaded with `next/font/local`. This makes the app render identically with no third-party request and no network (the sandbox's proxy blocks Chromium from fonts.googleapis.com, so the bake-off could only be rendered this way), removes a render-blocking dependency, and keeps a student's page loads out of Google's logs, which suits `PRIVACY.md`. The fonts are the same fonts.
39. **Tailwind's default palette, sizes, radii and shadows are replaced, not extended.** `apps/web/tailwind.config.ts` sets `theme.colors`, `fontSize`, `fontWeight`, `borderRadius` and `boxShadow` wholesale to `var(--…)` aliases of `apps/web/app/tokens.css`, so `bg-blue-500`, `text-xs`, `rounded-2xl` and `shadow-md` cannot be typed. Spacing keeps Tailwind's 4px grid; values off the scale (`p-5`, `p-7`) are review findings rather than compile errors. The `dark:` variant exists but is unused: tokens flip themselves.
40. **Urgency has six steps, not three tones.** The old `critical / warning / neutral` vocabulary drove red, amber and green pills. `lib/urgency.ts` now maps days remaining to a heat step 0–5 (more than 30, 15–30, 8–14, 4–7, 0–3, overdue) and screens color numbers and text with it; there are no urgency backgrounds or badges. Step 0 is secondary text, so a far deadline is silent.
41. **The command palette uses `cmdk` on top of the system dialog.** It is the one third-party UI dependency added; it provides filtering, keyboard navigation and ARIA for a list, and it renders unstyled, so every visible part comes from tokens. Lucide, tailwindcss-animate and class-variance-authority leave with `components/ui`.
42. **Builds can target their own output directory.** `next build` and `next dev` share `.next`, and a build while the dev server runs corrupts it; with seven page agents working against one dev server, nobody could verify a build. `next.config.ts` reads `NEXT_DIST_DIR` (default `.next`), so `NEXT_DIST_DIR=.next-build pnpm build` verifies a production build without touching the running server. `.next-build` is ignored and cleaned like `.next`.
43. **Screenshot shots live in one file per page area.** `apps/web/scripts/shots/<area>.ts` each export their own list and `index.ts` concatenates them, so parallel page work never edits the same file; the runner also lets a shot name its own dev account or run anonymous, and waits for the countdown settle and every finite animation before capturing, so no screenshot lands mid-motion.
44. **First sign-in creates the student row with an on-conflict insert.** A new account's first page load fires several authenticated requests at once, and every one ran the same "find, else insert" in `studentsRepo.upsertFromAuth`; the losers failed on the unique `auth_user_id` and the page rendered a 500 (found while screenshotting onboarding as a fresh student). The insert is now `ON CONFLICT DO NOTHING` on `auth_user_id`, and a loser re-reads the row. This is the one change outside the web app and the rename in this redesign; it is in `packages/shared`, not the agent runtime, and it fixes a bug real students would hit on their first visit.
