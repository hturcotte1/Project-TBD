# Decisions

Judgment calls made during the build, with reasons. Newest at the bottom.

1. **Package scope `@tbd/*`.** The repo is `Project-TBD`; the scope is short and won't collide. Rename is a find-and-replace.
2. **Agent name: Remy.** Configurable via `AGENT_NAME`. Short, warm, gender-neutral, easy to type.
3. **REST with a shared zod contract instead of tRPC.** The contract (`packages/shared/src/api/contract.ts`) is a list of route definitions with zod params/query/body/response. Fastify registers routes from it and the web app gets a typed client from it. This keeps the API callable from webhooks, curl, and the fake phone, and avoids tRPC's coupling to a React client.
4. **Fastify over Hono.** Mature plugin ecosystem for rate limiting, multipart uploads, and static files, which the dev phone and upload flows need.
5. **Clerk in production, dev-mode auth locally.** `AUTH_MODE=clerk` uses `@clerk/nextjs` on the web and `@clerk/backend` `verifyToken` on the API. `AUTH_MODE=dev` uses an HMAC-signed cookie and `/dev/login` so the entire product runs and is testable without vendor accounts. The API verifies bearer tokens through one `AuthVerifier` interface either way. Clerk could not be exercised in this sandbox (no keys); see KNOWN_GAPS.
6. **Web app talks only to the API.** No direct DB access from Next.js. One place enforces authorization. Client components go through `/api/proxy/*` so the token never leaves the server.
7. **Deterministic extraction first, Stagehand as fallback.** The reader navigates with Playwright, captures each page's HTML, and runs cheerio-based extractors from `commonapp-map.ts`. Those extractors are pure functions over HTML, so they run in tests against recorded fixtures with no browser. Stagehand `extract()` is used only when an extractor reports low confidence for a whole section (site drift). Stagehand v4 bundles zod 4 and its own driver, so it connects to the same Browserbase session over CDP rather than sharing the Playwright page.
8. **Verification codes go through Redis, never Postgres.** A `VerificationCodeChannel` (Redis list with 10-minute TTL) carries the code from the agent tool to the waiting browser job. The browser job stays in-process while waiting because a local Chromium session cannot be resumed by another process. Browserbase sessions are kept alive with the same in-process wait for consistency.
9. **Scheduler is a 5-minute tick plus pure trigger rules, not thousands of delayed jobs.** `evaluateTriggers(state, now)` is deterministic and fully unit-tested with a fixed clock. The tick enqueues jobs with deterministic ids so re-ticks are idempotent. The `nudges` table records what was sent per `triggerKey` so nothing repeats.
10. **Deadlines are dates, resolved to end-of-day in the student's timezone.** Common App treats deadlines as 11:59 pm applicant-local. Days remaining = calendar-day difference in the student's zone.
11. **LLM default `claude-sonnet-5`, strong model `claude-opus-5`.** The prompt asked for Sonnet as the runtime default and "the strongest available model" for high-stakes reasoning. Claude Fable 5.1 has different API constraints (no forced tool use, 30-day retention requirement) and higher cost; Opus 5 is the safe default for the strong tier. Both are env-overridable.
12. **`FakeLLM` is rule-based, not a stub.** Conversation tests assert on tool calls and DB state; the fake implements the persona's decision rules deterministically (intent → tool calls → reply) so the runtime, tools, repos, messaging, and audit paths are exercised end to end. Real-model behavior is verified separately when a key is present (`pnpm test:live`).
13. **Documents go to the LLM natively.** Transcript PDFs and images are sent as `document`/`image` blocks with structured output, so there is no PDF parsing library to maintain.
14. **Storage adapter is S3-compatible.** Supabase Storage exposes an S3 endpoint, so one `S3StorageProvider` covers Supabase and AWS. Local dev writes to `.data/storage` and serves via the API.
15. **Essay text is stored, never generated.** `saveEssayDraft` only accepts text that arrived in a student message or the dashboard editor. The essay-feedback prompt returns a structured `EssayFeedback` object with no `suggested_text` field, so even a compliant model cannot hand back prose.
16. **Autonomy level lives in config and the approval kind enum.** `AUTONOMY_LEVEL=B` rejects any approval of kind `submit`; level C would allow creating and executing them through the same `approvals` → `browser_jobs` path. The writer's submit guard is a separate, always-on runtime check that level C would relax explicitly for the `submit` job kind only.
17. **Subagent model.** All implementation subagents run on Sonnet; the orchestrator (this session) does architecture, review, integration, and verification.
18. **Job ids never contain a colon.** BullMQ rejects custom ids with `:` unless they happen to split into exactly three parts, which made `sync:<id>:<bucket>` work by accident and `inbound:<id>` fail at runtime. `jobIds` now joins with `__` and sanitizes components; the memory enqueuer enforces the same rule so tests catch it.
19. **Consumed verification codes are scrubbed from the student's own text.** The inbound message row is the only place a code could persist; the `answerVerificationCode` tool replaces it with `[verification code]` after publishing to the channel, whether or not a job was waiting.
20. **Relative paths resolve against the repo root.** `STORAGE_LOCAL_DIR=.data/storage` meant different directories to the API and the worker; `loadEnv()` now resolves relative paths from the directory containing `pnpm-workspace.yaml`.
21. **Item matching requires a descriptor.** "done with the Georgetown supp" must not mark an arbitrary Georgetown item done. `matchItem` needs a title or kind word (with student synonyms like "supp", "rec", "letter") and reports near-ties as ambiguous so the agent asks which one.
22. **Non-Common-App schools keep their supplements.** Georgetown's essays are tracked as internal-rule items the student marks done, since the reader cannot observe them.
23. **Regular Decision is the default plan when adding a school.** Early Decision is binding; it must be a deliberate choice, never a silent default from dataset ordering.
24. **Teacher-recommendation slots follow the invitations.** One item per required letter plus one per extra teacher actually invited (capped at the school's max), so an optional second letter is tracked once the student asks for it.
25. **Tests run serially at the root.** All packages share `DATABASE_URL_TEST`; Turbo's default parallelism made them truncate each other's tables.
26. **Sunday's weekly plan is enqueued for the coming week.** The trigger fires Sunday evening; the worker computes the following Monday as `week_start`.
